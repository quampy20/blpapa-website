# Implemented style guide

How the approved brand system in `BLPAPABrandandWebsiteStyleGuide.pdf` is
realized in code. `CLAUDE.md` §3 is the specification; this is the map from it
to the files.

Every colour pairing used for text in this stylesheet has been recomputed
against WCAG. `npm run check` re-verifies the mechanical parts on every build.

---

## Where things live

```
src/styles/
├── tokens.css              Palette, type ramp, spacing, radii — the whole vocabulary
├── fonts.css               Generated by tools/fetch-fonts.py. Do not hand-edit
├── base.css                Reset, element defaults, focus, skip link, .placeholder
├── layout.css              Containers, section bands, grids
└── components/
    ├── header.css          Sticky header, nav, mobile disclosure
    ├── footer.css          Navy footer
    ├── hero.css            Home hero, page heroes, event stamp, breadcrumb
    ├── buttons.css         The four button recipes
    ├── cards.css           Cards, tags, stats, people, callouts, detail lists
    ├── forms.css           Intake picker, fields, validation, preview notice
    ├── media.css           Photography, gallery, video link, press strip
    ├── article.css         Newsletter reading layout, timeline
    └── motifs.css          Cultural motifs — all decorative, all removable
```

The build concatenates these into one `site.css`, tokens first. Authoring stays
modular; the page pays for one request.

## Colour

The palette is transcribed from the style guide, not sampled from the logo. An
earlier session sampled the *old* logo and produced a different palette that
is now obsolete; `CLAUDE.md` §3 has that history.

### Roles

| Token | Value | Role |
|---|---|---|
| `--blpapa-navy` | `#042B34` | Structure: nav, headings, footer, primary buttons |
| `--blpapa-teal` | `#125657` | Reading: links, eyebrow labels, supporting headings |
| `--blpapa-ink` | `#0E1C20` | Body text |
| `--blpapa-green` | `#1A552A` | Programs and category accents |
| `--blpapa-cream` | `#F0E8D1` | Alternating section bands |
| `--blpapa-white` | `#FDFDFD` | Default background |
| `--blpapa-red-accessible` | `#B21A09` | Every small red element |
| `--blpapa-red` | `#D5230C` | Logo artwork and large display only |
| `--blpapa-gold` | `#FDCF06` | Accents and secondary buttons. Never text |
| `--blpapa-orange` | `#EB620F` | Sparing decorative accent |

### The two reds

The single easiest way to get this brand wrong.

- `#D5230C` **Bayanihan Red** is 4.21:1 on cream. That is a straight AA
  failure for body text. It lives inside the logo and in large decorative
  headings, nowhere else.
- `#B21A09` **Deep Red** is 5.64:1 on cream and 6.78:1 on white. Every link,
  label, button, and small red element uses this one.

Nothing in this stylesheet sets small text in `--blpapa-red`.

### Derived surfaces

Three tints were added, all verified. No new hues enter the system.

| Token | Value | Contrast with navy | Used for |
|---|---|---|---|
| `--surface-teal-tint` | `#E7EFEF` | 12.85:1 | Newsletter and story bands, callouts |
| `--surface-cream-deep` | `#E7DCBC` | 10.97:1 | Edges and rules on cream |
| `--color-text-muted` | `#3B4A4E` | 9.07:1 on white | Captions, hints, metadata |

### The 60 / 25 / 10 / 5 rule

The most useful constraint in the guide, and mostly enforced by `layout.css`
section classes rather than by discipline:

| Share | What | How it is enforced |
|---|---|---|
| 60% | White and cream | `.section`, `.section--cream` are the default bands |
| 25% | Navy and teal | `.section--navy` used sparingly, one per page at most |
| 10% | Green | Category accents on cards only |
| 5% | Red, gold, orange | Buttons, tags, motif rules |

> *"Let the logo and cultural imagery remain the most colorful elements."*

The logo is already vivid. A section that uses every brand colour is a bug.

## Type

Montserrat for headings, Noto Sans for body. Two families total.

**Self-hosted**, not loaded from Google. `CLAUDE.md` §2 bans shipping
third-party surveillance into a site serving a specific ethnic community, and
a Google Fonts request reports every visitor to Google before a word is drawn.
`tools/fetch-fonts.py` regenerates the local copies.

Only the weights actually used are downloaded — Montserrat 600 and 700, Noto
Sans 400 and 700, latin subset only. Each unused weight would cost about 35 KB
against a 500 KB page budget.

The ramp uses `clamp()` between mobile and the desktop sizes in the guide.
Body floors at **17px**: many readers here are older community members.

| Role | Token | Range |
|---|---|---|
| Hero | `--step-hero` | 34 → 64px |
| H1 | `--step-h1` | 32 → 48px |
| H2 | `--step-h2` | 24 → 36px |
| H3 | `--step-h3` | 20 → 24px |
| Body | `--step-body` | 17 → 18px |
| Lead | `--step-lead` | 19 → 22px |
| Small | `--step-small` | 15px |

## Cultural motifs

Drawn from the logo's own visual language rather than invented alongside it.
The set is closed at five — **baybayin is deliberately not in it**, despite an
earlier session planning to use it.

| Class | Motif | Implementation |
|---|---|---|
| `.motif-rays` | Philippine sun rays | `repeating-conic-gradient`, masked to fade upward |
| `.motif-weave` | Woven ribbon | `repeating-linear-gradient`, 6px tall |
| `.motif-rule` | Ribbon as a short section rule | Three-stop `linear-gradient` |
| `.motif-horizon` | Mountain landscape | Layered `radial-gradient` |
| `.motif-sampaguita` | Sampaguita blossom | Inline SVG mask, also `.list-sampaguita` bullets |
| `.motif-flag-tick` | Red-gold-blue flag cue | Three-stop `linear-gradient` |

Rules that apply to all of them:

- CSS gradients or inline SVG, never raster images
- `aria-hidden="true"` without exception
- Removable without losing information
- Prefixed `motif-` so they are easy to audit

The ray geometry follows the logo's sunrise — rays fanning from a low horizon
point — not the eight rays of the national flag. That distinction is the sort
of thing this audience notices.

## Accessibility

Requirements, not polish.

- Every text pairing passes WCAG AA; most reach AAA
- Focus is never removed. The ring is deep red, switching to gold on navy
  fields so it stays visible on every surface in the palette
- Colour never carries meaning alone — the current nav item gets a rule as
  well as a colour, form errors get a warning glyph and text, category cards
  get a written tag
- Touch targets are at least 44×44px
- `[id] { scroll-margin-top: 7rem }` keeps the sticky header off anchor targets
- `prefers-reduced-motion` disables transitions and smooth scrolling
- Placeholders for unverified content are loud by design: dashed red border,
  visible on the page, impossible to mistake for real content

## Page weight

The budget is 500 KB per page including images. `npm run check` fails the build
over it, counting the HTML, the stylesheet, the scripts, all four webfonts, and
the heaviest candidate from each `<picture>` or `srcset` group.

Current worst page is around 400 KB.

Two asset rules, which are opposites for a reason:

- **Logo marks ship as palette PNG.** They are flat illustration with hard
  edges, where a 256-colour PNG beats WebP outright — 41 KB against 58 KB at
  600px. A `<picture>` offering a larger WebP would be ceremony.
  (`tools/generate-logo-sizes.py`)
- **Photographs ship as WebP with a JPEG fallback.** The opposite case, and
  the only asset class heavy enough to threaten the budget.
  (`tools/optimize-photos.py`)
